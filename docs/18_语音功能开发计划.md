## 一、选型结论（已拍板）

| 项 | 结论 | 理由 |
|---|---|---|
| 引擎 | **GPT-SoVITS**，直接上 v5 整合包（`GPT-SoVITS-v5-20261005.7z`，10.9GB） | 1~5 分钟素材微调即可高相似度；日文数据训练→中文推理工作流成熟；Windows 整合包解压即用 |
| 路线 | **zero-shot 先验证全链**，满意后再决定是否微调提质 | 整合包自带底模 + 参考音频直接合成，无需训练；砍掉「先装 CosyVoice2/fish-speech 预验证」步骤（多套环境=多踩坑面，CosyVoice2 的 pynini 依赖在 Windows 是天坑） |
| 语言 | 中文推理 | 希亚对话为中文 |
| 红线 | **仅本地运行，不公开不分发** | 声音素材来自 galgame CV，仅个人玩具用途 |
| 显存 | 本机 GTX 1050 Ti **4GB**，v3+ 底模需开半精度 | qwen3.5:4b(4.1GB) 本就进不了 4GB 显存，LLM 与 TTS 显存天然解耦，TTS 独占 GPU |

### 2.3 声音素材管线（初恋1/1，SiglusEngine）
- 素材源：`F:\初恋1-1\初恋1比1\koe\`，327 个 `.ovk`（SiglusEngine 语音容器）
- **OVK 格式已破解**（自研逆向，GPT-SoVITS/tools/ovk_extract.py）：
  - TOC：`u32 count` + count×16B 记录 `[u32 size, u32 start, u32 id, u32 d]`
  - payload 为**明文 Ogg**（无 XOR），start_i+size_i 严格链到 start_{i+1}
  - 实测 100% 有效拆出；全量拆包输出 `GPT-SoVITS/_voices/`（2 万+ 条，持续增长）
- 场景标签表（scene.chs 头部 UTF-16LE）：`<字母><2位序号>_<角色名_台词号>`，b=共通 c=碧 d=雪乃 e=瑠奈 f=叶 g=摩耶(h/i/j=附录)
- 每个_ovk = 一个场景 = 基本同一角色 → 认声锁定摩耶场景即可整包提取
- 台词文本↔语音行号逐句映射：**未解**（scene.chs 实测=Scene.pck 解密版，正文为场景字节码；需啃 Siglus 场景格式，独立后续工程，不堵主线）

### 2.4 声学选角（用户附加任务，已完成终版结论）
- 任务：量化对比各角色声线，评「谁最配希亚人设」
- 助手无听觉，采用**声学代理**：F0 中位/p10/p90（音高音域）、频谱质心（明暗）、浊音占比、时长节奏
- 工具链（`GPT-SoVITS/tools/`）：
  - `voice_profile_fast.py`：向量化画像器（批帧 rfft 质心 + FFT 自相关 F0），soundfile 原生解码 ~50ms/条（ffmpeg 子进程方案 1.1s/条 已废弃）
  - `classify_v3.py`：锚点增强全量分类器，纯 CSV 查表秒级；摩耶锚点=ground truth 区间干净样本（voi≥0.6,dur≥1.0），其他角色=v1 高置信样本（dist≤0.6,≤80/类）bootstrap，阈值 1.6
  - `verify_v3.py`：ground truth 复验 + 电话段定位（hp3k=3.4kHz 以上能量占比，电话音效带限失真代理指标）

- **分类准确率演进**：v1 单锚点 64.7% → v3 锚点增强 **85.3%**（58/68，复验于 ground truth 区间）。误判集中于 <1s 短句与激动高音段（f0>300 漂向会长/雪乃），对统计结论无实质影响

## 四、环境雷与教训（回填区）

1. **backend/.venv 不可用**：从别机拷来，python 指向 `C:\Users\zhaoq\...`（本机无此用户）。需重建：`C:\Python311\python.exe -m venv .venv` + pip 装回 requirements。本机 Python 3.11.9 在 `C:\Python311\`。
2. scene.chs = Scene.pck 的解密同构版（头部逐字节一致），不是明文台词文件；14MB 里仅 193 个「。
3. ovk 的 z 编号散布（z0001…z9004/z9999），非连续分区；其 TOC id 是场景内局部行号，与名称表 4 位台词号不同体系且跨角色撞号。**ovk 内 id 也有空洞**（z0003 的 2029~2061 不存在），按 id 区间筛文件必须判存在。
4. 素材里零散事实：`F:\初恋1-1\摩耶\` 只有 3 张立绘 webp；`wav\` 是 BGM/BGV（.nwa）；ffmpeg/7z/Python 环境以本文为准。
5. **后台任务跨回合会被回收**（"task not found"）→ 长任务必须设计成**断点续跑**（分类器读已有 CSV 跳过已完成项，增量写盘），且优先前台执行。
6. **timeout 转后台的任务与手动续跑并发写同一 CSV 会产生重复行** → 读侧一律去重（`dedup[r["file"]] = r` 保留最后一条）。
7. **电话音效段会污染声学锚点**（带限失真 → 质心/F0 双双漂移）→ 用 hp3k（>3.4kHz 能量占比）可无听觉定位电话段；锚点筛选必须先过 hp3k。本作电话段：z0003_1991~2028。
8. WebFetch 拿不了二进制（7zr.exe 返回空）→ 用 curl.exe 下载；winget 装软件可能被中断 → 便携版优先。
9. GPT-SoVITS 整合包解压目录名（v2pro-20261006）与下载文件名（v5-20261005）不一致，hf-mirror 的包名与内部版本可能错位，以解压结果为准。
10. **Trae Shell 里 Start-Process 起的进程会被 job object 连坐清理**（静默死、0 字节日志，bat 包裹也无济于事）→ 长任务唯一可靠分离方式 = **bat + schtasks 计划任务**（`schtasks /create /tn X /tr "xxx.bat" /sc once /st 23:59 /f` + `schtasks /run /tn X`），进程树完全独立于 shell。
11. **schtasks /run 在前一任务实例未完全退出时会被静默忽略**（输出 "Attempted to run" 但 Last Run 更新后进程秒退）→ 重启前先确认任务 Status: Ready（杀 python 后等几秒再 /run）。
12. **1050Ti 跑 v2ProPlus 训练实测 8.5~11.5s/step**（batch 2 + grad_ckpt + fp16，GPU 100%/3997MiB 顶格）→ 6 小时全量数据跑多 epoch 是天量时间（30 epoch≈2 周）。**大数据量要配小 epoch**：精选 1500 条（1.5~12s 时长过滤 + 场景均匀采样 ≈ 91 分钟素材）× 3 epoch ≈ 7 小时，等效社区「短素材多 epoch」典型配方。预处理产物按文件名缓存，改清单重跑近乎零成本。
13. **s2_train 的 tqdm 进度条走 stderr**（重定向时进 err 文件），且 train.log 按 log_interval=100 才打一行 → 判断训练速度/存活看 err 文件的 tqdm `x/751 [mm:ss<..., s/it]` 行最准。
14. **s2_train 保存目录 `logs/<exp>/logs_s2_v2ProPlus/` 由 webui open1Ba 负责创建**，绕过 webui 直训必须提前 mkdir，否则 epoch 末 save_checkpoint 时 shutil.move 崩、权重丢失（e1 事故）。崩溃残留的临时文件 `G_<iteration>.pth.unTemporary` 可改名还原抢救；D 侧可用底模伪造（optimizer: None 会被 load_checkpoint 跳过）。
15. **后台 Popen/Start-Process 会被 shell 会话退出连坐杀**（job object）→ 长任务一律 schtasks 托管（`/create /sc once /st 23:59 /f` + `/run` 立即触发；`cmd /c` 被 shell 安全策略禁，/tr 直接挂 python.exe）。
14. **绕过 webui 直训 s2_train 必须自建 `logs/<exp>/logs_s2_<version>/` 目录**（webui open1Ba 里 os.makedirs，s2_train 自己不建）→ 缺失时 epoch 末 save_checkpoint 的 my_save（shutil.move 到不存在目录）崩溃，整个 epoch 白跑且 `returncode=1` 只在日志尾部一行，err 里 traceback 才见真相。
15. **epoch 崩溃后的抢救**：s2_train 启动自动 resume（try 加载 `logs_s2_*/D_*.pth + G_*.pth`，成功则 epoch+1 续训），但 G/D 必须同时在场。my_save 崩溃时 tmp 文件（`<ttime>.pth`）还躺在进程 cwd 包根——G 网络完整 state 可直接改名归位；D 缺失可伪造：`{"model": 底模s2Dv2ProPlus["weight"], "iteration": <已完成epoch>, "learning_rate": 1e-4, "optimizer": None}`，`load_checkpoint` 对 `optimizer is None` 会跳过加载（utils.py L28），D 从底模重来收敛极快，几乎零成本。
16. **s1_train（Lightning）在无终端环境输出被全缓冲**：err/log 停在模型摘要不动 + GPU 满载 = 正常在跑；精确进度用 tensorboard 的 event_accumulator 解析 `logs_s1_v2ProPlus/**/events*`（tags: total_loss_step / epoch / top_3_acc_step）。**s1 实测 0.32s/step**（比 s2 快 ~30 倍，每 epoch 仅 4 分钟）——GPT 微调远比 SoVITS 便宜。
17. **if_save_every_weights 的权重文件名带全局 step 后缀**（`maya_e3_s2253.pth`，2253=累计 step；中途恢复训练会重置计数器导致 e2 无后缀）→ 监听脚本等固定文件名会扑空，兜底：复制权重补名触发，或监听改用 glob（`maya_e10*.pth`）。**注意 s1_train 命名规则完全不同：`maya-e5.ckpt`（连字符 + .ckpt 后缀，无 step）**，两套 glob 不可混用。
18. **摩耶声线随剧情阶段系统性变化**（用户听感先于数据发现，tools/maya_stage_analysis.py 实证）：共通线(不熟) F0 258/质心1710/音域最窄（高冷克制）→ g 摩耶线(情侣初期) p90 348 音域打开（活泼外放）→ h/i/j 后日谈(if) F0 286/质心2347 全程最甜最亮。**全时期声线都珍责（用户拍板"我都爱"），用法=好感度映射**：intimacy_level(1陌生人/2朋友/3依赖者/4恋人) ↔ (共通线/g线/后日谈) 参考音频池，ref 按当前好感度阶段自动选，trust 0~100 做池内微调；第二层可选按阶段各训一份 SoVITS 实现音色级变化。
19. **api_v2 支持 `/set_gpt_weights` 与 `/set_sovits_weights` 热切换**（quote 过的路径参数）→ 对照实验方法：起 api(底模) → 合成对照组 → 切 e5 → 合成 → 切 e10，一次训练产出三方对比矩阵。GPT 微调 + 摩耶原声 ref(后日谈 z6005 / g线 z3007) + 中文合成 = 「全摩耶闭环」试听组合。
20. **`schtasks /sc once` 测试任务到点会真触发**：23:59 残留的一次性任务自动拉起 s1_train 空跑，留下 3KB 空 events 存根（version_3），「取最新 version」逻辑被劫持 → 监控曲线空白两小时。**用完的测试任务必须 `/delete`**。
21. **系统内存耗尽的报错很隐晦**：可用内存仅 426MB 时 s1_train 报 `MemoryError: Out of memory interning an attribute name`（看不出是内存问题）→ 主因是幽灵训练进程(1.3GB) + api_v2(600MB 内存+显存)共存。**开新训练前先 `wmic process where "name='python.exe'" get commandline` 查残留并清理**。另：s1_train 的 num_workers 设 0 会报 `prefetch_factor option could only be specified in multiprocessing`（DataLoader 写死传参）→ 只能取 1~2。
22. **手动关闭训练控制台窗口 = 训练静默被杀**（`forrtl: error (200): program aborting due to window-CLOSE event`）。对策三件套：① 启动 .cmd 自最小化（`if "%minimized%"=="" ( set minimized=true & start /min cmd /c "%~f0" & exit )`）；② schtasks 拉起；③ 监控页状态文案动态化（「(e8 训练中)」vs「(全部完成)」），避免用户看到歧义文案去关窗。
23. **schtasks 用的 .cmd 一律纯 ASCII 注释**：中文注释在 GBK 代码页下解析爆炸，症状包括命令行被截断成 `'rain.py' 不是内部或外部命令`。
24. **监控页 tfevents 选源两坑**：① glob 必须用 `version_*/events*`（events 在嵌套 version 目录里，顶层匹配为空）；② 「最新 version」不可靠（崩溃/空跑会留存根）→ **按 events 文件体积选数据源**，真训练（MB 级）永远压过 3KB 存根。
25. **Lightning 的 "Epoch 7/7" 是第 8 轮**（0-indexed），勿误判少训一轮；铁证 = 权重文件名 `maya_full-e8.ckpt`（0-indexed N ↔ e{N+1}）。全量数据实测 ~39 分/epoch（精选 ~10 分），监控页速度显示要看数据量。
26. **openclaw 更新 2026.10.8 连环坑**：① Node 引擎墙 `>=24.22.1 <25 || >=26.12.1`，MSI 升级解决；② npm 11.19.1 默认拦截 postinstall → `npm i -g openclaw --allow-scripts=...` 白名单重装；③ 服务注册变幽灵（配置登记但任务不存在）→ start/uninstall/doctor 全卡死 `ScheduledTaskInspectionError (0x80070005)`，杀残留 node 进程后只能数据重置；④ **agent 库 schema 19→20 迁移不可逆**，旧版 2026.9.2 拒载，doctor --fix 也过不了服务检查；⑤ onboard 向导最后写 key 时 payload 是陈旧快照（缺前序插件配置），被 `size-drop` 防覆盖保护拦截（「Config write rejected (size-drop:1272->576)」）→ **修法：`openclaw models auth paste-api-key --provider deepseek --profile-id "<向导生成的profile id>"` 单独补 key**；⑥ 配置缺 `gateway.mode` 段 → 从 .bak 抄 token 手工补齐；⑦ 服务层全灭时兜底 = 前台 `openclaw gateway run --port 18789`（schtasks + 自最小化 .cmd，即 `openclaw_gw_run.cmd`）。
27. **faster-whisper 在本 runtime 不可用**：`ctranslate2.dll` 加载失败（缺依赖）→ 中文 ASR 用整合包自带 funasr（`AutoModel`，ms/hf 双源 fallback）。
28. **funasr 官方封装会自动选 cuda**（`device="cuda" if available`）→ 训练占卡时跑 ASR 必须自建 AutoModel 强制 `device="cpu"`，否则显存连坐。
29. **v2Pro 自带说话人验证模型 = 门禁3 现成工具**：`pretrained_models/sv/pretrained_eres2netv2w24s4ep4.ckpt` + `GPT_SoVITS/sv.py::SV.compute_embedding3`（20480 维 embedding，CPU 可跑）。注意 `import kaldi` 是 `GPT_SoVITS/eres2net/kaldi.py` 本地模块，加载需 **cwd=包根**（sv.py 内相对路径依赖）。MFCC 余弦相似度实测无区分力（所有女声对比 0.96+，音素差异淹没音色差异）→ 音色归属必须用此 embedding。
30. **F0 风格分化被 GPT 压扁**（2026-10-28 实测）：ref 音高差 40Hz（akuma 281 / wenrou 241），合成音全挤在 264~292Hz 窄带；全量 e8 甚至方向反转（akuma 264 < wenrou 277），精选 e20 方向正确但差距仅 8Hz。微调 GPT 存在「向均值回归」效应，风格个性要靠分档 ref 池 + 推理参数补。
31. **数据资产最终格局（2026-10-28 清理 12GB 后）**：`_training/wav/`（7453 条 32k wav，训练唯一输入，maya.list 指向）保留；`_ssu_out/`（37450 条 KOE 原始提取）与 `_voices/`（z*.ogg 中间层）已删——wav 转换已完成，将来清洗对照实验直接操作 wav，不回 ogg；原始提取清单备份在 `_training/koe_master.csv.bak`。
32. **三道门禁评测设施**（评审 19 号文档第六节落地）：`_audition/gate/sentences.json`（20 句固定集：5 温柔/5 傲娇/5 含数字/5 长难句）+ `tools/eval_gate.py`（synth 切权重合成 / score 评分：CER<0.10（funasr 强制 CPU）、RMS 尾首>0.6、ERes2NetV2 音色 sim、附 F0 中位）+ `tools/chain_gate_eval.py`（等 e16 落盘+训练退出 → 自动合成 4 档×20 句 → 评分出 report JSON）。以后任何新权重/新路线，同一测试集一键量化对比，不靠耳朵猜。

33. **绕过 webui 直训 RVC 必须自建 config.json + filelist.txt**（2026-10-28 21:40 实测）：`train/utils.py:get_hparams()` 硬读 `./logs/<exp>/config.json`，且 `hparams.data.training_files` 写死为 `./logs/<exp>/filelist.txt`（utils.py:389）。这两个文件平时由 **webui.py 训练入口**生成（:961 写 filelist，:975-985 写 config），链脚本若跳过 webui 就必然 `FileNotFoundError`。要点：① config 在 **sr=40k 时一律取 `configs/v1/40k.json`**（webui.py:971，`version19=="v1" or sr2=="40k"` 都走 v1 分支，与 `-v v2` 无关）；② filelist 取四个子目录（`0_gt_wavs` / `3_feature768` / `2a_f0` / `2b-f0nsf`）**文件名交集**，行格式 `<gt>.wav|<fea>.npy|<f0>.wav.npy|<f0nsf>.wav.npy|<spk_id>`，webui 写盘时把 `\` 转义成 `\\`；③ 已封装为 `tools/rvc_prepare_expdir.py --exp maya_svc --sr 40k`（支持 --dry-run），以后重建实验目录直接跑。
34. **RVC 预训练底模路径要带 `assets/` 前缀**：本包底模在 `assets/pretrained_v2/f0G40k.pth`、`assets/pretrained_v2/f0D40k.pth`，**不是** `pretrained_v2/`。`-pg/-pd` 写错的表现是 config.json 已修好、`get_hparams()` 也过了，却在 `train.py:254 torch.load(hps.pretrainG)` 才炸 FileNotFoundError（报错点离根因很远，容易误判）。
35. **RVC 权重产物名与转换脚本期望名不一致（链上断点）**：`train.py` 只往 `logs/<exp>/` 写 `G_<global_step>.pth` / `D_<global_step>.pth`；而 `svc_convert.py:pick_weight()` 与 `chain_svc_convert.py:weight_ready()` 找的是 `assets/weights/*maya_svc_e*.pth`，且后者还要求 `train_log.txt` 出现 `ALL DONE`。**没有任何环节负责这个搬运与标记** → 训练成功也会让转换链永远空转。已补 `tools/svc_finish_chain.py`：等 GPU 释放（连续 3 次 <300MB 防 epoch 间隙误判）→ 导出 `maya_svc_e<step>.pth` → 建 faiss 索引 → 变声 20 句 → 评分 → 写 `ALL DONE`。
