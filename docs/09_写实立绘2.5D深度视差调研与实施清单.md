# 写实立绘 2.5D 深度视差 调研报告 + 实施清单

> 调研日期：2026-10-11。调研背景：前端「写实立绘」路线（`frontend/src/components/stage/StageSprite.vue`）目前是静态图 + CSS transform。用户明确要求升级为**动态、略带写实**的形象，并已拍板走 **2.5D 深度视差**（而非纯 3D / VRM）。
>
> 与本文档的姊妹篇：`08_Live2D升级调研与实施清单.md`（另一条形象路线，真 Live2D，情绪 + 口型驱动）。两条路线并存，互不替代。

---

## 一、结论摘要

1. 运行时用**项目已有的 PixiJS v8**做自定义 Filter（不必再引 Three.js），复用现有 WebGL 上下文管理方式。
2. 深度图**离线预生成**：用 SD WebUI 的 ControlNet `depth_midas` 出图时顺手导出（零安装、零运行时开销），不用浏览器端实时估计。
3. 效果核心是一个**片元着色器**：按深度值缩放 UV 偏移，实现"近处动得多、远处动得少"的真视差。
4. 情绪与日/夜切换通过 **uniform 参数**驱动，不换组件、不重载资源。

---

## 二、为什么是 2.5D 而不是纯 3D

| 维度 | 2.5D 深度视差 | 纯 3D（VRM + Three.js） |
|---|---|---|
| 画风保留 | 像素级保留 SDXL 插画质感（painterly anime realism，正是"略带写实"的来源） | 必然转为 cel-shaded 3D 渲染感，丢掉"写实"差异点 |
| 形象一致性 | 白发 / 左红右金异色瞳 / 花店打光 = 插画本身 | 需从零制作希亚专属 VRM 模型 |
| 与路线 A 的关系 | 与真 Live2D 形成风格差异，两条路线并存有意义 | 与 Live2D 同属"模型动画"，视觉定位趋同 |
| 日/夜切换 | 换一对图 + 一对深度图即可 | 需调实时光照，复杂度高一个量级 |
| 硬件 | 一个 WebGL 片元着色器，GTX 1050Ti 无压力 | Three.js + VRM 实时渲染，4GB 显存吃力 |
| 工作量 | 多产一张深度图 + 一个 shader | 建模 / 绑骨 / 表情 morph / 口型 |
| 效果上限 | 仅深度位移，**不能真转头或换姿势** | 真转头、真口型、自由运镜 |

**结论**：只有当项目明确需要"真转头 / 真姿势变化 / 自由运镜"且愿意专门制作 VRM 模型时，纯 3D 才更优。当前定位（半写实插画 + 动态）下，2.5D 是结构性更优解。

## 三、运行时方案对比

| 方案 | 依赖 | 实现方式 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|---|
| **PixiJS v8 自定义 Filter** | 项目已装 `pixi.js@^8` | 一个 Sprite + 自定义 `Filter`，片元着色器按深度缩放 UV | 复用现有依赖与上下文管理；GLSL/WGSL 双后端；与 Live2D 组件同技术栈 | 需自己写片元着色器 | **推荐** |
| PixiJS v8 内置 `DisplacementFilter` | 同上 | 位移贴图驱动 | 开箱即用 | 位移是全画面统一强度，**不是按深度缩放的真视差**；边缘易拉扯 | 不满足需求 |
| Three.js 独立 Plane + ShaderMaterial | 新增 `three` | 一个平面 + 深度着色器 | 生态成熟、示例多 | 额外引入 3D 引擎与第二个渲染上下文；`@promontis/threejs-pom` 还需 WebGPU 与 TSL | 备选 |
| 纯 DOM 多层 PNG + CSS transform | 无 | 把插画预切成背景 / 人物 / 雪花图层，各层不同速位移 | 零 shader、实现最快 | 需要**预切图层**（依赖 See-through 类工具，重）；层间边缘会露缝，无逐像素连续性 | 不推荐 |

> PixiJS v8 的 Filter 同时提供 glsl 与 wgsl 实现，WebGL / WebGPU 两种渲染器都能跑；自定义 Filter 的官方基类为 `Filter`。

### 关键实现点

1. **必须是自定义 Filter**，不能用 `DisplacementFilter`。后者把位移贴图当成"统一方向的偏移量"，而深度视差要求位移量与深度成比例。
2. **深度图用红通道**（标准灰度 PNG 的 R=G=B，等价）；约定 **白 = 近，黑 = 远**。
3. **边缘保护三件套**（防黑边 / 拉伸）：
   - Sprite 预放大 1.05~1.10（沿用现有立绘 `scale: 1.08` 的思路）
   - 深度图**膨胀（dilate）**处理，让前景边缘外扩再采样
   - 片元里对 UV 做 `clamp`
4. **视差强度上限**：偏移过大时会出现"纸片感"和拉丝，建议 `uStrength` 上限控制在画面宽度的 3%~5%。

### 片元着色器（概念示意，非最终代码）

```glsl
// uniforms: uSampler(插画) / uDepth(深度图) / uPointer(归一化指针) / uStrength(视差强度) / uBreath(呼吸相位)
float d = texture2D(uDepth, vTextureCoord).r;      // 白=近
vec2  uv = vTextureCoord;
vec2  dir = uv - vec2(0.5);                        // 以画面中心为原点

uv += dir * (d - 0.5) * uStrength;                 // 静态深度视差（近处外扩更多）
uv += uPointer * (d - 0.5) * uStrength;            // 鼠标跟随视差
uv = clamp(uv, 0.001, 0.999);                      // 边缘保护

gl_FragColor = texture2D(uSampler, uv);
```

## 四、深度图（depth map）来源对比

| 方案 | 位置 | 质量 | 成本 | 结论 |
|---|---|---|---|---|
| **SD WebUI ControlNet `depth_midas` 导出** | 出图端（离线） | 可控，与原图同源同分辨率 | 出图时多一步"Preview / 导出预处理图" | **推荐**：SD WebUI 本就装着 SDXL 与 `controlnet++_union_sdxl_promax`，零安装 |
| ComfyUI `DepthAnything_V2` 节点 | 出图端（离线） | 质量更好（2024 至今社区默认） | 需 `comfyui_controlnet_aux` 自定义节点；**注意**：本项目 ComfyUI 以 `--disable-all-custom-nodes` 启动，该节点不会加载；新版本 ComfyUI 已原生支持 Depth Anything 3 节点，需确认当前版本 | 备选 |
| `BrokenSource/DepthFlow`（Python） | 出图端（离线） | 好，且能直接导出视差视频预览 | 额外装 Python 工具链 | 可用于**做效果预览** |
| 浏览器端 `transformers.js` + Depth Anything V2 Small ONNX | 前端（运行时） | 一般（small 档） | 模型约 278 MB，首屏需下载 + WebGPU/WASM 推理；`runonweb/depth` 封装了该流程（Apache-2.0） | **不推荐**：对伴侣类应用首屏体感伤害大 |

**决策**：深度图**离线预生成并随插画一起入库**（如 `stage-realistic-night.png` + `stage-realistic-night-depth.png`），前端只做加载与渲染。

## 六、推荐落地方案

### 6.1 数据与资源

- 每套形象 = **插画 + 深度图** 两张，按日/夜成对：
  - `frontend/public/avatars/stage-realistic-night.png` / `-night-depth.png`
  - `frontend/public/avatars/stage-realistic-day.png` / `-day-depth.png`
- 深度图规格：与插画**同分辨率**、8 位灰度 PNG、白=近。
- ⚠️ **面部一致性基线（2026-10-11 用户定调）**
  - 用户满意**当前伪动图立绘 `stage-main.png` 里希亚的五官与脸**，要求后续所有希亚形象**以此脸为基准**。
  - 允许变化：发色（日=暖黄白 / 夜=冷蓝白）、瞳色（异色瞳左红右金）；**不允许变化：脸型与五官**（眼型、鼻、唇、轮廓）。
  - 现行 `stage-main.png` 本身≈"银蓝发 + 雪夜"，天然接近**夜版**基调 → 直接作夜版面部母版。
  - 出图手段：**禁止纯 txt2img 从零生成**；以 `stage-main.png` 作面部参考——**img2img 低重绘（denoise 0.3~0.5）** 或 **IP-Adapter FaceID / ControlNet reference-only**；并沿用原图 PNG metadata 的 seed 与底模参数（AnythingXL_xl + SDXLVAE）作底座。

### 6.2 前端改动

| 文件 | 改动 |
|---|---|
| `frontend/src/config/sprite.ts` | 新增日/夜**插画 + 深度图**四条路径；保留现有 `MAIN_SPRITE` 作为回退 |
| 新增 `frontend/src/components/stage/StageParallax.vue` | PixiJS v8 Application + Sprite + 自定义 Filter；接管指针、呼吸、情绪、日/夜 |
| `frontend/src/components/stage/StageSprite.vue` | 若 WebGL 不可用则回退到现有 `<img>` + CSS 方案（渐进增强，不破坏现状） |
| `frontend/src/views/StageView.vue` | 「写实立绘」入口挂到新组件 |
| `frontend/src/stores/ui.ts` | 复用现有 `theme`（day / night）选择图片与深度图，无需新增状态 |

### 6.3 参数与驱动

**情绪驱动（uniform，不换资源）**

| 情绪 | `uStrength` | 呼吸频率 | 附加 |
|---|---|---|---|
| 平静 / 默认 | 基准值 | 基准 | — |
| happy | ↑ 略高 | ↑ | 轻微上浮 |
| sad / anxious | ↓ | ↓ | 轻微下沉 + 降饱和 |
| surprised | ↑↑ 瞬时脉冲后回落 | — | 一次性 |
| dizzy | ↑↑ | ↑↑ | 复用现有发晕逻辑 |

**日/夜切换**：换插画 + 深度图纹理对；色调差异由出图端保证（暖黄白 vs 冷蓝白），前端不额外调色。

### 6.4 与 Live2D 路线的共存约束

现有 Live2dStage 已建立**全局单实例 WebGL 上下文注册表**（避免多上下文泄漏与回收）。新的视差组件必须：

1. 复用同一套单实例注册表语义，保证任一时刻只有一个 `Application` 存活；
2. 在 `import.meta.hot.dispose()` 中主动回收上下文；
3. 两条路线由 HUD 按钮互斥切换，不做同屏叠加渲染。

## 七、风险与边界

| 风险 | 表现 | 对策 |
|---|---|---|
| 边缘拉伸 / 黑边 | 视差偏移采样到画外 | Sprite 预放大 + 深度图膨胀 + UV clamp |
| 纸片感 | 偏移强度过大 | 限制 `uStrength` 上限；先做小强度验证 |
| 深度图与插画不对位 | 人物边缘错位 | 深度图必须由**同一张插画**同源生成，禁止缩放/裁剪后再用 |
| WebGL 上下文冲突 | 与 Live2D 组件争抢 | 复用单实例注册表；互斥切换 |
| 移动端 / 低端设备 | 掉帧或黑屏 | 看门狗检测 + 自动回退到静态 `<img>` 方案 |
| 深度图质量不足 | 前景边缘糊、发丝粘连 | 出图端做一次深度图膨胀与对比度拉伸；必要时换 Depth Anything V2 档位 |

## 八、实施清单（待用户确认后执行）

1. **出图端**：夜版插画定稿后，用 ControlNet `depth_midas` 导出同源深度图（白=近），命名 `-depth.png`。
2. **出图端**：以夜版为 ControlNet depth 母版出日版，同样导出日版深度图。
3. **前端**：`sprite.ts` 增加日/夜 插画 + 深度图 路径。
4. **前端**：新建 `StageParallax.vue`（PixiJS v8 Application + Sprite + 自定义深度 Filter），先实现静态深度视差 + 鼠标视差。
5. **前端**：接入呼吸微动与边缘保护（预放大 + 膨胀 + clamp）。
6. **前端**：接情绪 uniform（复用 `emotionAnim.ts` 的 mood 语义）。
7. **前端**：接 `ui.theme` 完成日/夜切换。
8. **前端**：WebGL 不可用 / 上下文丢失时回退到现有 `<img>` 静态方案。
9. **验证**：`npm run type-check`；浏览器截图对比"鼠标移动前后的视差位移"；确认与 Live2D 路线互斥切换无上下文泄漏。
