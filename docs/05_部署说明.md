# 05 部署说明（希亚 AI 女友 · 后端 + 前端）

> 本文覆盖从零到跑通的完整部署流程：环境要求 → 后端 → Ollama 模型 → 前端 → 旧数据导入 → 测试 → 常见问题。
> 架构与配置项的代码级说明见 [02_详细设计.md](02_详细设计.md)，接口清单见 [03_API文档.md](03_API文档.md)。

## 1. 环境要求

| 组件 | 版本要求 | 用途 | 说明 |
|------|---------|------|------|
| Python | **3.11** | 后端运行 | 开发实测 3.11.9；依赖列表见 `backend/requirements.txt` |
| Node.js | **20.19+** | 前端构建 | Vite 7 的最低要求（^20.19.0 \|\| >=22.12.0），Node 18 会导致 `npm run dev/build` 直接报错 |
| Ollama | 任意近期版本 | 本地 LLM 通道（主力） | https://ollama.com 下载安装 |
| ffmpeg | 任意近期版本 | 语音识别转码 | 需加入 PATH；否则用 `.env` 的 `FFMPEG_PATH` 指定完整路径 |
| Vosk 中文模型 | `vosk-model-cn-0.22`（约 2GB） | 语音识别 | 不入 Git，见 2.4 步骤 |
| git | 可选 | 拉取代码 | 项目仓库：`d:\workspace\xia-ai`（main 分支） |

> 语音功能（STT/TTS）为可选外设：不装 Vosk 模型/ffmpeg 不影响文字对话，仅 `/api/voice/stt` 返回 422。

## 2. 后端部署步骤

### 2.1 创建虚拟环境并安装依赖

```powershell
cd d:\workspace\xia-ai\backend
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

### 2.2 配置 `.env`

```powershell
Copy-Item .env.example .env
```

然后编辑 `backend/.env`，逐项说明（均可留默认，只有前两项按需必填）：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `DASHSCOPE_API_KEY` | 空 | **在线通道密钥（阿里云 dashscope）**。只用本地 Ollama 时可留空；一旦 `LLM_CHANNEL=auto` 且本地不可用、或 `online` 模式，无 key 会请求失败。⚠️ V13 源码中硬编码的旧 key 已泄漏，务必作废重发后填新 key |
| `QWEN_MODEL` / `QWEN_URL` | `qwen-plus` / dashscope 官方端点 | 在线模型与端点，一般不改 |
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | 本地 Ollama 服务地址 |
| `OLLAMA_MODEL` | `qwen3.5:4b` | 本地模型名，须与 `ollama pull` 的名称一致 |
| `LLM_CHANNEL` | `auto` | `auto`=本地优先失败切在线 / `local`=仅本地 / `online`=仅在线 |
| `LLM_LOCAL_TIMEOUT` | `60` | 本地通道超时秒数，超时视为不可用 |
| `WEATHER_API_KEY` / `WEATHER_HOST` / `WEATHER_CITY_ID` | 空 / 空 / `101210701` | 和风天气（雷雨关怀联动）。key/host 未配置则**静默跳过**雷雨检测，不影响其他功能 |
| `DATA_DIR` | `./data` | SQLite、chroma 记忆库、滚动日志的根目录（相对 `backend\`） |
| `TTS_VOICE` | `zh-CN-XiaoyiNeural` | edge-tts 默认音色 |
| `VOSK_MODEL_PATH` | `./models/vosk-model-cn-0.22` | STT 模型目录（相对 `backend\`，见 2.4） |
| `FFMPEG_PATH` | `ffmpeg` | ffmpeg 可执行文件；不在 PATH 时填绝对路径 |
| `USER_NAME` / `USER_BIRTHDAY` | `小叶` / `04-06` | 用户画像初始默认值（之后可在前端画像页编辑，存 DB） |
| `API_HOST` / `API_PORT` | `127.0.0.1` / `8900` | 后端监听地址与端口 |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | 允许的前端来源（逗号分隔），见第 7.4 节 |

密钥只放 `.env`（已不入 Git），`backend/.env.example` 仅为模板。

### 2.3 启动后端

```powershell
cd d:\workspace\xia-ai\backend
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8900
```

启动时自动幂等建表（SQLite `data/xia.db`）。验证：

```powershell
curl http://127.0.0.1:8900/api/health
```

预期返回 `{"status":"ok","llm":{...}}`，其中 `active_provider` 显示当前实际通道（`local` 或 `online`）。

### 2.4 Vosk 中文模型（仅语音识别需要）

1. 到官方模型列表 https://alphacephei.com/vosk/models 下载 `vosk-model-cn-0.22`（约 2GB）；
2. 解压到 `backend\models\vosk-model-cn-0.22`（与默认 `VOSK_MODEL_PATH` 一致；放别处则改 `.env`）。

模型首次加载较慢，之后进程内只加载一次。TTS（edge-tts）无需任何模型，但合成时需要外网。

## 4. 前端部署步骤

```powershell
cd d:\workspace\xia-ai\frontend
npm install
npm run dev
```

- 开发服务器运行在 **http://localhost:5173**，`/api` 请求自动代理到 `http://127.0.0.1:8900`（见 `vite.config.ts`），开发态无 CORS 问题；
- 生产构建：

```powershell
npm run build      # 先 vue-tsc 类型检查，再 vite build，产物在 dist/
npm run preview    # 本地预览构建产物
```

**PWA 说明**（`vite-plugin-pwa`，`registerType: autoUpdate`）：

- `npm run build` 产物 `dist/` 内含 Service Worker（`sw.js`）与 `manifest.webmanifest`，js/css/html 全量预缓存，立绘 `/avatars/` 走运行时 CacheFirst 缓存；
- Service Worker 仅在 **localhost 或 HTTPS** 下注册；局域网 IP 以 HTTP 访问时 PWA 安装与离线能力不可用（页面功能不受影响）；
- 部署 `dist/` 到任意静态服务器时，需把 `/api` 反向代理到后端 8900 端口（开发态等价能力由 Vite 代理提供）。

## 5. 旧数据导入（可选，V13 真实用户数据迁移）

前置条件：仓库存在 `_legacy\立绘化与pwa支持\` 留档目录（含 `chat_history.json`、`personality_state.json`、旧 chroma `memory_db\`）。

```powershell
cd d:\workspace\xia-ai\backend
.venv\Scripts\python tools\import_legacy.py
```

导入内容与幂等性：

| 数据 | 去向 | 幂等策略 |
|------|------|---------|
| `chat_history.json` | messages 表（保留原情绪标签与时间戳） | 表内已有数据则整体跳过 |
| `personality_state.json` | personality_state 表（留档 trust=25 / level=2） | 仅在表为默认空值（trust=0/level=1）时覆盖 |
| 旧 chroma `memory_db\` | 新 chroma 记忆库（按文本去重重嵌入） | 逐条按文档文本去重，可重复执行 |

建议**先导入再启动服务**；重复执行无副作用。旧 chroma 0.4.x 库通过直接读其 sqlite 元数据迁移，跨版本稳定。

## 7. 常见问题

### 7.1 LLM 通道回退行为

- `LLM_CHANNEL=auto`（默认）：每次选 Provider 前对本地 Ollama 做健康探测（3 秒超时），通过则走本地，失败则告警并回退在线 dashscope；**选择结果缓存 60 秒 TTL**，不会每个请求都探测；
- 已选定本地后，单次 chat 失败（连接失败/超时/模型未 pull）会抛 `LLMError`，接口返回 **502**，不做单次调用内重试，等下一次探测周期自动切通道；
- 回退到在线通道需要 `DASHSCOPE_API_KEY` 已配置，否则在线请求也会失败（同样 502）；
- `local` / `online` 为强制单通道模式，失败即 502。可通过 `/api/health` 查看当前实际通道。

### 7.2 天气 key 未配置时

`WEATHER_API_KEY` / `WEATHER_HOST` 任一为空即静默跳过雷雨检测：不报错、不注入雷雨关怀 prompt、不发送雷雨通知，其余功能完全正常。配置后每轮对话前会实时调用和风天气（5 秒超时），任何异常同样静默降级。

### 7.3 `/api/voice/stt` 返回 422 的可能原因

接口在识别结果为空时统一返回 422「未能识别到有效语音」，常见根因按概率排序：

1. **Vosk 模型目录不存在或路径错**：检查 `VOSK_MODEL_PATH` 指向的目录是否包含模型文件（首次调用日志会输出「找不到 Vosk 模型目录」）；
2. **ffmpeg 不可用**：`ffmpeg` 不在 PATH 且未设 `FFMPEG_PATH`，转码失败（日志见「FFmpeg 转码失败」）；
3. **录音内容无法识别**：录音为空、过短、噪音大或非中文语音；
4. **vosk Python 包问题**：未安装或与 Python 版本不兼容（`pip install vosk==0.3.45`）。

排查入口：滚动日志 `data/logs/xia.log`。

### 7.4 CORS 跨域

- 后端仅放行 `CORS_ORIGINS` 中列出的来源（默认 localhost:5173 / 127.0.0.1:5173）；
- 开发态前端走 Vite 代理（同源转发），本就不触发 CORS；**只有前端静态部署在其他地址/端口**（如 `http://192.168.x.x:4173`）才需要把该来源追加进 `CORS_ORIGINS` 并重启后端；
- 手机 PWA 以局域网 IP 访问时同理，需把 `http://<电脑IP>:5173`（或静态托管地址）加入白名单。

### 7.5 端口约定

后端 8900（`API_PORT`）、前端开发服务器 5173（`vite.config.ts`）。修改任一端后，需同步检查前端代理目标与 `CORS_ORIGINS`。
