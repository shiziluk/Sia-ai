# Sia-ai 项目助手工作规则（长期有效）

> 来源：2026-10 前后多轮协作中用户反复强调的指令、纠正与偏好，整理固化而成。
> 执行优先级：用户最新指令 > 本文档 > 项目记忆旧记录。修订须经用户确认。

## 一、沟通与汇报

1. **汇报简短直接**，但阶段性收尾归纳要**详细、分条编号**（用户明确偏好 granular 总结）。
2. 交付物（图片/报告/文件）一律带 `computer://` 预览链接；源码引用用 `file:///` 链接。
3. **允许且应当驳斥**用户的错误判断，基于实际观察给出真实结论，不一味迎合。
4. **一次只推进一件事**，不擅自并行多任务；阶段间等用户确认再继续。
5. 用户说「我去洗澡了/离开了」= 固定动作：①更新留档文档（「下次第一件事」置顶）②git commit + push。
6. 用户验收打回时，**问题清单原样记录**进留档，作为下次挑图/修复标准，不美化不省略。

## 二、验证纪律（最核心）

1. **改完必须验证**：程序化验证（运行日志/像素扫线）+ 视觉验证（截图/诊断图）双确认。
2. **出图类必须先自查再交付**：生成后拼「原型 vs 生成」对比图自查，禁止把原始输出直接扔给用户。
3. **迭代版本化**：输出文件带 vN 版本号（v5/v6/v7…），旧版保留可回滚；**用户验收通过后才清理**废件；失败即回档到最近留档版本重试。
4. **修图类用深色底检查边缘**：品红/绿底会掩盖同色系描边，深色底（模拟前端实际观感）才是有效检验。
5. 逐像素扫线是定位边缘/抠图问题的最可靠手段；先扫线取证，再下结论。

## 二A、运行后复盘入档（2026-10-12 用户定：持续进步规则）

1. **每次运行（生成管线/脚本调试/部署排障）结束后，必须做一次「复盘入档」**：把本轮发现的可行方法（下次直接复用）与踩过的坑（下次不再犯）写进对应文档——生图相关写 [docs/13](file:///d:/workspace/Sia-ai/docs/13_生图全流程自检体系.md) 复盘小节，系统环境/工具类写本文档 §五，进度类写 docs/10。
2. 复盘粒度：每条「方法/坑」都要带**触发条件与解法**（可执行，不是感想）；坑注明「下次不再犯」的具体规避动作。
3. 这是让助手在运行中不断进步的机制——规则库随每轮运行单调增长，禁止同一坑踩第二次。

## 三、出图工作流（希亚形象）

0. **生图全流程自检体系（2026-10-12 起长期遵从）**：生图前预检 → 出图程序化检查 → 抠图预检 → 逐视图自检 → 对比图自查 → 闭环留档，六个阶段逐项过，先自查再交付。完整检查表见 [docs/13_生图全流程自检体系.md](file:///d:/workspace/Sia-ai/docs/13_生图全流程自检体系.md)。
1. **纯色背景规则**：单独生成角色外表图/三视图设定图，背景一律纯色（绿幕），方便抠图。
2. **形象生成验收规则**：生成后必须拼「原型 vs 生成」并排对比图（`sia_out/make_compare.py`），以三张基准原型图（见第 2a 条）及用户特意发来的参考图为基准逐项对比（脸/服装/姿势/画风/解剖结构/发长），**力求还原；不符合就重新生成或打磨，直到用户验收通过**。
2a. **三图基准规则（2026-10-12 用户定）**：以后生成希亚形象（Live2D 形象素材、未来 2.5 画风 3D 形象），**不管是普通图片还是三视图，一律先以这三张图为原型参考**：
   - [frontend/public/avatars/stage-main.png](file:///d:/workspace/Sia-ai/frontend/public/avatars/stage-main.png)（面部基准）
   - [sia_out/sia_char_magenta_00001_.png](file:///d:/workspace/Sia-ai/sia_out/sia_char_magenta_00001_.png)（黑丝版原型）
   - [sia_out/sia_char_magenta_00002_.png](file:///d:/workspace/Sia-ai/sia_out/sia_char_magenta_00002_.png)（围裙版原型）
   ⚠️ **黑丝瑕疵警示**：00001 原型本身有「希亚一只脚没有黑丝」的瑕疵——这是原型的缺陷，**生成时必须双腿黑丝完整，不复刻该瑕疵**；挑图时单脚缺黑丝 = 直接打回。
2b. **Live2D 素材生成规则（2026-10-12 用户定，后续工作必须遵守）**：生成 Live2D 用形象素材（真 Live2D 委托素材与假 Live2D 分层素材都适用）时：
   - **形象跨图统一**：头发长度、服装、体型在各图/各差分间必须完全一致，零漂移（多动作变化的前提是形象统一）
   - **手部必须可见且姿势可动**（手臂要能活动）：禁止 `hands behind back` 等藏手/挡手姿势，改用手自然垂在身侧等分层友好姿势；手部崩坏风险靠 negative + 加大 batch 重抽消化
   - **表情反应体系**：必须预建表情差分，响应用户两类输入——①文字信息（情绪标签映射）②鼠标点击身体部位（普通部位如头/身 与 敏感部位 要有**不同的反应设计**）
   - 多动作变化（多姿势差分）以「形象统一 + 分层可动」为前提逐步扩展
2c. **鬼图销毁规则（2026-10-12 用户定）**：「废图」不作统一界定——助手认为该删的图用户可能觉得有可取之处，反之亦然，因此**普通废图一律保留待用户验收，助手不擅自删**。但例外：检测到**让人看到会造成精神冲击、精神震撼或掉 san 值**的图（俗称鬼图：严重解剖崩坏成恐怖形态、五官崩坏进恐怖谷、倒转头/多肢扭曲等诡异超常画面）时，**立即删除，不得出现在交付列表里，不让用户看到**。删除后在留档/日志记一笔（文件名 + 删除原因），保持可追溯。
3. **基准资产永不清理**：两张品红原型图、`frontend/public/avatars/stage-main.png`（面部基线）。废件清理清单永远排除它们。
4. **面部一致性**：所有新形象以 stage-main.png 的五官脸型为基准，不得修改面部特征；锁脸用 inpaint 蒙版（脸区不涂蒙版），不用 FaceID（锁身份不锁像素五官，denoise 高了脸会漂）。
5. **结构级错误重抽优先**：反关节/多腿/手消失/头脚倒转这类解剖崩坏 inpaint 修不动，加大 batch 重抽 + 严格挑图；inpaint 只修小杂（鞋色/局部瑕疵）。
6. **多视图挑图清单**：四肢关节方向、肢体数量、手是否正常、服装正背逻辑（围裙正面/背带背面）、裙长裙色视图间一致、发长、头发与身体是否混合、左右对称。
6a. **大批量前先单张验证（2026-10-12 经验固化）**：批量生成 ≥4 张前，必须先跑 1 张走通全链路（加载/IPAdapter/采样/落盘）并做程序化检查，确认无白跑风险后再放量；若该批次方向新颖（新姿势/新服装/新构图），样张先给用户定方向再全量（用户不在场则跑完再交）。
6b. **差分图实现手段（补充 §三.2b）**：表情/姿势差分一律用 ComfyUI 蒙版 inpaint 继承原图 seed 与底座参数（脸区不涂蒙版锁死），**禁止从零 txt2img 重抽差分**——txt2img 必然形象漂移，违背零漂移要求。
7. **人设约束**：希亚自我认同是「人造意识/千年旅者」，**绝不能自称 AI**；"AI" 只允许以她痛恨的贬低标签出现（设定冲突的戏剧引擎）。
8. **分工**：SD 出图用户自己在绘世启动器 GUI 手动出（助手负责提示词/参数/工作流说明 + 出图后接前端）；程序化批处理任务走 ComfyUI API——优先朋友桌面端（192.168.1.9:8188，速度快），朋友端不可用时**本机 ComfyUI 兜底**（见 §五.6）。
9. **ComfyUI 约束**：不手写 extra_model_paths.yaml（用户自己在启动器配）；大文件走 `/upload/image` 的 bridge_share；inpaint 对贴人物窄掩膜会脑补色晕，能本地程序化处理就不走 SD。

## 五、系统环境教训（Windows / PowerShell 5.1）

1. PowerShell 5.1 **不支持 `&&`**，用 `;` 分隔；含中文的 `.ps1` 必须 UTF-8 BOM。
2. `curl.exe` 发 JSON 时内层引号会被吞——发消息用 `Invoke-RestMethod` + UTF8 字节 body。
3. pip 直调 `pip.exe` 会失败，用 `python -m pip`；pytest 用 `--no-cov`（覆盖率门禁 80% 是历史遗留不达标）。
4. 出图输出目录固定 `d:\workspace\Sia-ai\sia_out\`；临时脚本用 `_tmp_` / `_diag_` 前缀命名便于清理，**任务收尾即清理临时文件**（正式产出转正后随之删 `_tmp_` 版）。
5. **国内下载模型走 hf-mirror.com 镜像**（2026-10-12 实测：RMBG-1.4 168MB 下载成功）；huggingface.co 直连在公司网络不可靠。
