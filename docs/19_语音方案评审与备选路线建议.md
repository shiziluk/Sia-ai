## 一、架构判断：音色与韵律必须拆开看

GPT-SoVITS 的两个模块职责不同，这一点决定了双模式该怎么设计：

| 模块 | 承载什么 | 与语言的关系 | 双模式是否共用 |
|---|---|---|---|
| **SoVITS**（s2） | 音色 / 说话人身份 | 跨语言稳定 | **共用一套，正确** |
| **GPT**（s1） | 韵律 / 语气 / 停顿习惯 | 与语言强绑定 | 需按语言分别引导 |

```
中文台词 ──► GPT 韵律（中文习惯）──┐
                                  ├─► SoVITS 摩耶音色权重（共用）──► 合成音频
日文台词 ──► GPT 韵律（摩耶原生）──┘
```

**结论**：现行方案「共用同一套 SoVITS 微调权重，无需分开训练」在架构层面完全成立，本文无异议。
**但要补一句**：这套说法只对 SoVITS 成立。GPT 是否也能共用，取决于它的训练语料是否覆盖中文（见第三节）。

## 二、核心瓶颈：摩耶没有中文语音

这是整个任务的天花板，建议在后续所有决策前先达成共识：

- 摩耶是日文 galgame 角色，**客观上不存在她的中文语音**。
- 用户已明确否决原神中文配音作为参考音频来源（2026-10-27 记录）。
- 因此中文模式的"地道中文韵律"**只能从外部引入**，无法从摩耶自身语料中学到。

### 2.1 一个容易被误判的机制 `[待验证]`

`[判断]` GPT-SoVITS 做跨语言克隆时，**音色能迁移，但口音会带上训练语言的底色**。也就是说：

> 只要 GPT 只吃摩耶的日文语料，中文输出的"日语腔"很可能是**结构性**的，不是训练不足导致的，训得越久反而可能越固化。

对 10-27 记录中「e10 对比 base 和 e5 日语腔已有明显消退」这一观察，本文给出另一种解释：

`[判断]` 消退的原因更可能是**韵律变稳定了**（不再乱飘、不再被参考音频带着跑），而不是中文发音真的变地道了。

**这两者的区分方式完全不同，必须实测**：

| 验证项 | 方法 | 判据 |
|---|---|---|
| 中文发音保真度 | 固定 20 句中文测试集 → Whisper/SenseVoice 转写 → 算 CER | CER < 8% 才算发音层面过关 |
| 中文韵律地道度 | 同一批句子做**盲听打分**（找 1~2 位中文母语者，不打标签） | 与目标文本情绪的吻合度 |
| 音色归属 | 说话人 embedding 与摩耶原声余弦相似度 | 见第五节门禁三 |

**建议**：不要再用"整体听感变好了"代替分项验证。整体听感改善可能来自韵律稳定，而发音问题被掩盖。

## 三、对方案 C 的三点异议

### 异议 1：不等验收就启动，顺序反了 `[判断]`

现行做法是「不等 e3 验收即可在 GPU 空闲时启动」。本文建议的顺序是：

```
① 清洗数据
② SoVITS 训练 → 盲听确认音色达标   ← 这是天花板，不达标后面全白做
③ 再决定 GPT 要不要微调、微调多狠
④ 最后才考虑全量数据 / 长时间训练
```

理由：
- **音色是上限。** 如果 SoVITS 阶段摩耶的音色相似度就不够，GPT 微调再久也救不回来。
- **成本不对称。** 1050Ti 4GB 上跑全量 8 epoch GPT 训练要占一整晚 GPU；方向错了，这一晚是纯损失。
- **方案 C 本身没有错**，错的是"在不知道 SoVITS 是否达标的前提下就梭哈"。

> 注：如果 e15/e20 的盲听已经确认音色达标，那么这条异议自动失效，现行的并行推进是合理的。**请以音色盲听结果为准，不必为这条异议回滚任何已完成的训练。**

### 异议 2：7453 条全量灌入，不清洗 `[判断，优先级最高]`

2026-10-27 记录：「用户明确要求将所有摩耶语音文件（共 7453 条）全部纳入训练，无需排除任何内容」。

**本文认为这是一个会导致效果下降的决定，建议重新考虑。**

理由：TTS 训练中**数据质量远大于数据量**。7453 条全量里已知包含：

| 污染源 | 影响 |
|---|---|
| 电话音效段（z0003_1991~2028 一带） | 带通滤波会扭曲频谱，直接污染音色建模 |
| 带 BGM / 环境音的段 | SoVITS 会把伴奏当成人声的一部分学进去 |
| 极短（<1s）/ 爆音 / 削波段 | 提供无效甚至有害的梯度 |
| 含其他角色对白的段 | 混入他人音色 |

**建议改为**：UVR5 去伴奏 → VAD 切 3~12s → 去爆音去重 → 日语 ASR 打标 → 抽 10% 人工核对，**清洗后保留 2000~3000 条高质量段**。

`[判断]` 清洗后的 2500 条，大概率比全量 7453 条效果更好，且训练更快（4GB 显存下这点尤其重要）。

> 这是本文最希望被执行的一条。如果坚持全量，至少做一次**对照实验**：清洗版 2500 条 vs 全量 7453 条，各自训到同一 epoch，同 ref 同台词对比，用数据说话。

### 异议 3：GPT 只吃日文语料，中文会退化 `[判断]`

见第二节。如果 GPT 微调语料 100% 是日文，那么：

- 日文模式：语气还原好，符合预期 ✓
- 中文模式：可能继承日语韵律底色 ✗

**建议的修正**（三选一，按推荐度排序）：

1. **混合语料微调**：日文摩耶原声（学语气情绪）+ 一份中文女声语料（保中文韵律），中文语料占比 15%~30%。低学习率、只微调部分层。
2. **中文模式单独用底模 GPT** + 摩耶 SoVITS，不走微调 GPT。
3. 微调后**每 2 epoch 回测中文 CER 与听感**，劣化立即回滚到上一个 checkpoint。（无论选 1 还是 2，这条都该做）

## 四、备选路线：中文模式走两段式 SVC `[未在本项目评估过]`

这是本文提出、现行方案未考虑过的路线，建议拿出低成本先验证一次。

### 4.1 思路

```
中文台词 → 中文音源念稿（真人 / 高质量中文 TTS）→ SVC 变声（摩耶音色）→ 成品
```

- **韵律**由中文音源保证 → 地道中文，从根上绕开"日语腔"
- **音色**由 SVC 迁移 → 还是摩耶
- 这是中文 galgame 同人配音圈的主流做法

### 4.2 与纯 TTS 路线的对比

| 维度 | A · 纯 TTS 微调（现行） | C · 两段式 SVC |
|---|---|---|
| 中文韵律 | 受训练语言底色影响 `[待验证]` | 由中文音源直接保证，上限高 |
| 音色相似度 | 高（SoVITS 直接建模） | 取决于 SVC 模型质量 |
| 管线复杂度 | 单段 | 两段，多一次推理延迟 |
| 额外依赖 | 无 | 需一个中文音源 + RVC/So-VITS-SVC 模型 |
| 日文模式 | 天然支持 | 不适用（日文仍走 A） |

### 4.3 建议的验证方式（低成本）

- 找 10 分钟可用的中文女声素材（用户自录 / 可自用的授权素材）
- 训一个 SVC 小样（RVC 对 4GB 显存友好）
- 用同一句中文台词，产出 TTS 直出版 vs SVC 版，**盲听二选一**

`[判断]` 这个验证半天就能出结果，但可能直接解决纠结最久的"AI 感 + 后段发软"问题——因为这两个症状的根源之一正是韵律与音色被同一个模型硬凑。

## 五、好感度分档：不建议训三个模型

目标（共通线高冷 → 低好感度 / g 线活泼 → 中 / 后日谈甜妹 → 高）本文完全认同。但**实现方式建议换成轻量方案**：

| 手段 | 做法 | 成本 |
|---|---|---|
| **分档 ref 库**（主力） | 三个时期各挑 3~5 条该时期摩耶原声作固定参考音频 | 零 |
| **推理参数档位** | 每档配一套 语速 / temperature / top_p | 零 |
| **文本风格约束** | 高冷档用短句书面语，甜妹档用语气词 | 零 |
| 训练数据分档加权 | 按档位给训练样本加权 | 中 |
| 训三套模型 | — | **4GB 显存下不现实，不建议** |

**一条来自记录的提醒**：用户过往认可的参考音频**全部集中在摩耶线（情侣初期）和后日谈阶段，共通线不熟期样本从未被认可**。这意味着"高冷档"可能需要靠**参数与文本约束**去造，而不是指望模型自动产出——因为用户自己可能并不真的喜欢那个时期的声线。建议先拿 3 条共通线样本给用户试听，确认这档是否真要保留。

## 六、验收门禁：从一道扩到三道

现行只有 ASR 文本回验，建议补齐另外两道，把"靠耳朵猜"变成可量化：

| 门禁 | 检测内容 | 工具 | 建议阈值 |
|---|---|---|---|
| 1 · 文本一致 | 合成音频转写 vs 目标文本 | Whisper large-v3 / SenseVoice | CER < 8% |
| 2 · 能量曲线 | **专治"后半句发软无力"** | librosa 算 RMS 包络，比对首尾段能量衰减比 | 后段/前段 RMS 比 > 0.6 |
| 3 · 音色归属 | 合成音频 vs 摩耶原声 | 说话人 embedding 余弦相似度 | > 0.75 `[阈值需按本机实测校准]` |

门禁 2 是直接对着用户最在意的症状设计的，建议优先实现。
