# 生图全流程自检体系（长期遵从）

> 建立日期：2026-10-12。来源：v5→v9 四轮迭代 + v8/v5 两份验收问题清单 + 绿幕抠图三轮踩坑（色距/绿幕合成/RMBG 语义）的固化管理。
> 效力：助手每轮生图任务**必须**按本体系执行，先自查再交付，禁止把原始输出直接扔给用户。
> 上位规则见 [docs/11_助手工作规则.md](file:///d:/workspace/Sia-ai/docs/11_助手工作规则.md) §二/§三；本文档是其「出图工作流」的细化检查表。
> 素材案例：v8 抠图实测（RMBG 语义保留高领但有绿雾残留；色距法干净但误抠灰绿高领）——两法组合是正式抠图方案。

## 阶段 0：生图前预检（提交工作流之前，纸面检查）

### 0.1 提示词检查表
- [ ] **形象要素齐全**：脸（大圆眼红瞳腮红）/ 发（silver long straight + blunt bangs + waist-length 1.4）/ 服装（按任务对应 outfit）/ 姿势（full body + hands behind back）/ 背景（green screen 1.5）逐项在 prompt 中有落点
- [ ] **围裙正背逻辑显式**：`(apron on front only:1.3), (X-shaped back straps:1.3), (bow on front:1.2), (no apron on back:1.2)`——v8 最高频错误，缺一条就重查
- [ ] **发长压制**：prompt `waist-length hair:1.4` + negative `(floor-length hair:1.4), (hair touching ground:1.4)` 双向锁
- [ ] **negative 解剖词组齐全**：extra limbs / third leg / missing arms / reversed joints / twisted feet / backwards head / fused legs / hair merging with body（v8 打回清单逐词映射）
- [ ] **背景预期管理**：SD 对 `green screen` 实际出青绿 RGB(69,191,151) 而非纯绿——不指望提示词治，靠阶段 2 组合抠图兜底

### 0.2 参数检查表
- [ ] 分辨率 **1440×960**（脸部精致度质变的最低门槛，见 docs/10 §二.4）
- [ ] IPAdapter 三坑：preset 全名 `PLUS (high strength)` / `embeds_scaling: V only` / weight_type 合法值（`linear` / `style transfer` / `style transfer precise`）
- [ ] 参考图必须是绿幕底（ref_green.py 处理过）+ 头肩特写（脸传递强且不拽构图）
- [ ] batch 策略：4GB 显存 → batch1 × seed+i 循环（等价 batch6）；大显存机器可 batch6
- [ ] seed 版本化换新，prefix 带 vN 版本号

### 0.3 批量策略检查表
- [ ] **大批量（≥4 张）前先单张验证**：1 张走通全链路 + 程序化检查，无白跑风险再放量（docs/11 §三.6a）
- [ ] 方向新颖的批次（新姿势/新服装/新构图）：样张先给用户定方向再全量
- [ ] 算力分层：朋友桌面端优先（快）；本机 4GB 兜底机 SDXL 禁 batch>1，用 batch1 × seed+i 循环，适合用户不在场时挂机长跑（docs/11 §五.6）

## 阶段 1：出图即时检查（程序化，每张必过，无需人眼）

生成脚本尾部自动执行（已在 three_view_ipadapter*.py 内置）：
1. **任务状态**：error 即停，错误详情打印；completed 才落盘
2. **绿幕纯净度**：四角 + 顶部中带 RGB 均值与 std——角落 std<1 为合格（全图渐变属预期，靠抠图兜底）
3. **fg 占比**（色距 T=50）：合理区间 **30~45%**。超出 = 崩图 / 人物缺失 / 背景杂物过多，直接标记待查
4. **mid-row fg px**：画面中横线前景像素数（v9 基准 ~800px），骤降 = 视图断裂
5. **文件完整性**：尺寸 1440×960、大小 ~800-1200KB；异常小 = 黑图/崩图

## 阶段 2：抠图预检（走抠图时）

1. **两法组合**（固定方案）：「色距法可靠连通背景」从「RMBG 语义前景」中扣除
   - RMBG（cutout_rmbg.py，onnxruntime）：语义人像，**高领/围裙保留**（色距法会误抠）
   - 色距连通域（cutout_00002.py 逻辑）：**绿雾清除**（RMBG 会残留青绿渐变）
2. 检查表：
   - [ ] fg ratio 30~45%
   - [ ] 灰绿高领完整保留（在深色底检查，§二.4）
   - [ ] 无绿雾残留（人物间隙/脚边）
   - [ ] 边缘无绿色描边/光晕（发丝、鞋边重点扫）
   - [ ] 发丝细部保留率

## 阶段 3：逐视图人工级自检（主推图必过，对照 §〇 验收标准）

对每张候选图逐视图检查（v8/v5 打回清单固化）：
1. [ ] 四肢关节方向：无反关节、无头倒转、无双脚反转朝观众
2. [ ] 肢体数量：无第三条腿、无多臂、无两条大腿不分离
3. [ ] 手：藏手（hands behind back）可接受但**不能有「手完全消失」的诡异感**；可见手则无畸形
4. [ ] 服装正背逻辑：围裙只在正面、背面仅 X 型背带（两条都在、左右对称）、无蝴蝶结画在背面
5. [ ] 裙长/裙色视图间一致（正面及膝 → 侧面不得变及踝）
6. [ ] 发长：不过腰太多、不拖地、不与身体/胳膊混合
7. [ ] 头发与身体分离（无「头发长在胳膊上」）
8. [ ] 多视图前后逻辑：标背面视图就真是背面，无 180° 转头诡异姿势
9. [ ] 脸贴原型：大圆眼红瞳腮红（对照对比图）
10. [ ] 画风：厚涂精致，无简笔化/线稿化

## 阶段 4：对比图自查（强制关口，§三.2）

1. `make_compare.py` 拼「左原型右生成」并排图（比对基准：品红原型 00001/00002 + 用户参考图）
2. 对比项：脸 / 服装 / 姿势 / 画风 / 解剖结构 / 发长——逐项过，不凭印象
3. **助手 Read 看图自查通过后才可交付**；自查不过 → 回阶段 0 调整重抽，不交付半成品
4. 接近合格的图（仅小杂）→ inpaint 局部修；结构级错误（反关节/多腿/手消失/头倒转）→ **重抽优先**，inpaint 修不动（§三.5）

## 阶段 5：闭环留档

1. 用户验收问题清单**原样记录**进 [docs/10](file:///d:/workspace/Sia-ai/docs/10_希亚立绘资产进度留档.md) §〇，作为下轮挑图标准（§一.6，不美化不省略）
2. 每条问题映射对策（提示词 / negative / 参数 / 重抽 / inpaint）写进「下次行动」
3. 新踩的坑回写本文档对应阶段（体系本身持续迭代）

## ⚠️ 反面案例库（2026-10-12 v9 验收建立：用户标注 4 张 + 助手自查 8 张，不能再犯）

### 用户指出的四类错误（提示词与挑图双向封锁）

1. **发长/发梢落点错误**：发梢拖到小腿、拖地、从裙下穿出、发丝与腿混合
   → prompt `(hair ends at waist level:1.3)`；negative `(hair touching ground:1.4), (hair between legs:1.3), (hair merging with legs:1.3)`
2. **围裙（花店服饰）前后样式错误**：X 型背带穿到正面、围裙兜/围裙布画到背面、半身视图胸前围裙结构错乱
   → 正面证据：`apron on front only` + `X-shaped back straps`；挑图时逐视图查"正面只见围裙、背面只见 X 背带+蝴蝶结"
3. **双腿没区分开**：两条腿贴死/肌肉混成一体、脚掌朝向反常（内八穿帮）
   → prompt `(legs slightly apart:1.2)`；negative `(fused legs:1.3), (twisted feet:1.4)`（已有，挑图时逐视图看脚掌朝向）
4. **手消失 / 手部姿态没有设计**（Live2D 手臂要能活动，只有手臂没有手不行）
   → 反面：袖口空无手、手完全消失无手形。prompt 必须写明手部姿态（如 `(hands at sides:1.2)` / `(hands clasped in front:1.2)`），并在 prompt 中"设计"手势；挑图时每个视图确认手可见且有形

### 助手补充的四类新发现（同批 8 张自查得出）

5. **头发"假尾巴"束**：披发被画成一束马尾状垂在裙后/裆间，像长了一条尾巴
   → negative `(ponytail:1.2), (hair tied:1.2), (braided:1.2)`；挑图时查披发是否呈自然披散
6. **设定图杂物**：服装分离件（单独画的围裙/背带）、头雕分解、色卡圆片、空白矩形块——SD 把"character sheet"理解成设定图格式就会出
   → negative `(clothing layups:1.3), (separate outfit pieces:1.3), (color palette:1.4), (head sculpture:1.3), (white boxes:1.3)`；负面词已有 props 类，这批补齐设定图专属词
7. **视图姿势/构图不统一**：走路/前倾/趴倒姿势混入站立三视图、半身特写与全身混排、构图炸裂（人物挤一侧+背景杂物）
   → prompt `(all views standing still:1.3), (same standing pose in all views:1.3), (all full body:1.3)`
8. **标准背景色（用户定色）**：v9 青绿背景 RGB(73,197,148) 用户认可，**定为希亚形象标准背景色**
   → 最可控做法：生成不必纠结色值（SD 对色名响应不稳），**抠图后统一把 alpha 底填充该色值**；prompt 保持 `(sage green background:1.5)`

### 对标行业标准的新发现（2026-10-12 上网对照 turnaround/服装结构规范得出）

> 参考：角色设定图（character turnaround）行业规范 + pinafore 围裙服装结构规范（来源见对话检索）。

9. **视图水平对齐缺失**：行业标准用水平辅助线保证**头顶/肩线/腰/膝在所有视图水平对齐**——我们生成的图各视图高矮参差、大小不一
   → prompt `(all views same height and scale:1.3), (views aligned horizontally:1.2)`；挑图时横向扫一遍头顶连线是否水平
10. **左右事实（left-right facts）漂移**：行业规范「一个设计旋转，不改配件数量与左右位置」——我们的图蝴蝶结时有时无、背带左右不对称、围裙口袋视图间漂移
    → 挑图新增检查项：**配件数量 + 左右位置逐视图一致**（蝴蝶结/背带/口袋/发饰逐个数）
11. **中立姿势规范**：行业做法先出「完全中立站姿」（身体笔直、双臂自然垂放身侧、手指自然微曲、不插兜不背手不叉腰）审计通过后再做动作——正与我们 Live2D 素材需求一致
    → prompt `(neutral standing pose:1.3), (arms hanging naturally at sides:1.3), (hands relaxed and visible:1.3)`；**取代笼统的 hands at sides**
12. **围裙结构规范（pinafore 构造确认）**：正面＝胸兜+裙身+腰系带结；背面＝**仅 X 交叉背带+腰结+收褶裙**，正面无交叉带、背面无胸兜，两者互斥——与三图基准 00002 原型一致
    → 挑图按此结构逐视图核对；v9 apron_00004 的「X 背带穿正面」即违反此规范
13. **视图顺序规范**：行业标准排列 front → 3/4 → side → back（从左到右）——SD 生成顺序随机且会重复视图，裁切挑视图时按此序重排；单图内视图数量以 3（正/侧/背）为目标，出现第 4/5 视图时选信息量最大的三张

### 对标 pixiv 实例图的新发现（2026-10-12，pixivision 通道，参考图存档 sia_out/_tmp_ref_pose_2/3.jpg）

14. **手部姿态必须有具体「手势设计」**：正确参照＝指关节分明的捏/握/垂（拇指与四指对握结构清晰），哪怕小动作手也有造型；我们的反面＝手消失/袖口空/手无结构。→ prompt 把手势写具体（如 `holding skirt hem` / `hands clasped in front`），Live2D 素材至少沉淀一套标准手型差分
15. **手-布料交互形变**：裙摆/围裙被手接触处应有张力形变（布料跟随手提起产生弧线），不是平贴——v9 围裙全程平贴无交互正是「无手」的连带后果
    → 挑图新增：布料与手接触处自然；仅手垂身侧的图不检查此项

### 对标 pixiv 原图的新发现（2026-10-12，pixiv.re 反代通道，参考图 _tmp_ref_px_1/2/3.jpg + _tmp_ref_px_sheet.jpg）

16. **发丝与身体的前后层次**：正确参照＝长发有分缕**穿插在手臂/身体前后**（精灵图：发从肩后绕到身前、压过手臂再垂落）；我们的反面＝头发是「贴身一整片」或「假尾巴束」，与手臂零层次。→ prompt `(hair strands over shoulder:1.2), (hair flowing behind body:1.2)`；挑图查发丝与手臂的前后穿插关系
17. **白色系服装靠结构细节撑**：白裙/白围裙的质感来自荷叶边/分片/系带/口袋等结构边缘线，不是一大片死白——v9 围裙即大片死白。→ prompt `(frilled apron:1.2), (layered apron:1.2), (apron with pockets and trim:1.2)`

### 多视图姿势模板规范（2026-10-12 用户定：定一次模板，以后所有多视图生成复用，不重摆）

> 来源：动画行业 turnaround 标准（cgwire 2026 / pixiv.io 教程）整合。摆姿势工具 = PoseMy.Art（动漫素体）或 JustSketchMe；摆好存为模板项目，永久复用。

**统一姿势规范（所有视图共同遵守）**：
1. 身体笔直中立站姿，重心居中双腿（不偏侧、不叉腰、不插兜）
2. **双臂自然垂放身侧，上臂与躯干之间留约一拳空隙**（手臂微离身体——保证手臂与手完整可见，Live2D 手臂分层的前提）
3. 手指自然微曲放松，不握拳不张开
4. 双腿微分（约一拳间距），不并拢不交叉
5. 头部水平正视（正/背视图），侧视图目视正前方；不歪头不低头
6. 长发自然披散，发梢止于腰；**背面视图头发拨至一侧露出背部结构**（希亚的 X 背带必须可见，不被头发盖死）
7. 全视图同尺度，头顶/肩/腰/膝水平对齐

**视图集定义（按用途选）**：
| 视图集 | 构成（从左到右） | 用途 |
|---|---|---|
| 三视图 | 正面 → 侧面 → 背面 | 基础形象定稿（当前 v10） |
| 五视图 | 正面 → 3/4右前 → 右侧面 → 背面 → 3/4左前 | 立绘/Live2D 素材标准 |
| 六视图 | 五视图 + 背 3/4（或左侧面） | 3D 化前的完整 turnaround |
| +表情行 | 下排 6 个头肩特写（中性/开心/生气/害羞/惊讶/难过） | 假 Live2D 表情差分（对应 docs/12 阶段1） |

**ControlNet 姿势锁定管线**：模板姿势截图 → OpenposePreprocessor 提取骨架 → ControlNet++ union promax（openpose，strength 0.75，end_percent 0.85）锁定生成。姿势源模板存 `sia_out/_pose_templates/`（与生成图分开）。

**视图生成策略（2026-10-12 用户授权助手定）：逐视图生成 + 程序拼接，不做一张图挤多人**
- 理由：一张图 5-6 人时单视图脸仅 ~60px（v9 教训），脸部必崩；ControlNet 逐张锁姿势后每视图全尺寸生成，脸最大
- 执行：PoseMy.Art 摆一套「标准中立站姿」→ 导出 6 角度截图（正/3-4右前/右侧/背3-4右/背面/3-4左前）存 _pose_templates/ → 三视图取 3 张、五视图取 5 张、六视图全用 → 每张单独 ControlNet 生成 → 程序拼接成设定图
- 表情差分不拼进多视图图，单独一轮蒙版 inpaint 批量出（质量更高，见 docs/12 阶段1）
- 排版拼接时按行业标准：从左到右 正→3-4→侧→背，间距均匀，头顶对齐
